# End-to-End Study of RNN, LSTM and GRU for Sequence Learning and Video Understanding

**CS3807 – Deep Learning Laboratory, Experiment 6 - RNN/LSTM/GRU on UCI HAR, UCF101 and a Synthetic Seq2Seq Task**

A controlled comparison of Vanilla RNN, LSTM and GRU under identical settings, extended to
video action recognition with a CNN + recurrent pipeline, and to sequence-to-sequence
learning with an encoder–decoder LSTM, on three datasets: UCI HAR, a small UCF101 subset, and
a synthetic digit-reversal task.

## Overview

This project covers the full pipeline end to end:

- Dataset loading via the UCI HAR raw inertial signal files (not the 561-feature vectors),
  windowed as $128 \times 9$ tensors; a balanced 2,400-window laboratory subset (400 per
  class across the 6 activities) split 70/15/15, with the test set held out untouched until
  final evaluation
- A hand-worked Backpropagation Through Time numerical exercise, cross-checked against a
  single-unit Keras `SimpleRNN` with identical weights
- RNN vs. LSTM vs. GRU classification under identical architecture, optimizer, batch size
  and epoch budget, compared on accuracy, macro precision/recall/F1, parameter count and
  training time
- Confusion-matrix analysis across all three recurrent models
- An effect-of-sequence-length study (T = 32, 64, 128) isolating how much each architecture
  depends on long-range temporal context
- Video understanding: 10 frames sampled per video, frozen MobileNetV2 feature extraction
  (feature dim 1280), then an LSTM/GRU classifier on a small UCF101 subset
  (Basketball / Biking / TennisSwing)
- Sequence-to-sequence learning: an encoder–decoder LSTM trained with teacher forcing on a
  synthetic 4-digit reversal task, evaluated with token accuracy and (stricter) sequence
  accuracy
- All 25 discussion questions from the lab manual, answered directly
- 7 additional exercises: unit-count sweep (16/32/64), GRU vs. LSTM at equal units, a
  stacked 2-layer recurrent model, Bidirectional LSTM, sequence length vs. training time,
  CNN-GRU vs. CNN-LSTM on video, and a harder variable-length seq2seq task (run-length
  collapse instead of plain reversal)

## Results

| Metric | RNN | LSTM | GRU |
|--------|-----|------|-----|
| Accuracy (%) | 77.22 | 95.83 | 96.67 |
| Macro Precision (%) | 77.40 | 96.40 | 96.83 |
| Macro Recall (%) | 77.22 | 95.83 | 96.67 |
| Macro F1 (%) | 76.97 | 95.80 | 96.65 |
| Parameters | 1,974 | 6,006 | 4,758 |
| Training Time (s) | 29.80 | 23.47 | 19.88 |

| Task | Result |
|------|--------|
| CNN-LSTM video accuracy (Basketball/Biking/TennisSwing) | 100.00% (4-video test set) |
| Seq2Seq reversal - Token / Sequence Accuracy | 100.00% / 100.00% |
| Seq2Seq variable-length (run-length collapse) - Sequence Accuracy | 85.22% |

GRU came out ahead of both RNN and LSTM on accuracy, F1 and training time simultaneously,
while also using fewer parameters than LSTM - there was no real complexity/performance
trade-off to weigh here. RNN's biggest weakness was confusing the three walking-type
activities (WALKING / WALKING_UPSTAIRS / WALKING_DOWNSTAIRS); LSTM and GRU fixed that almost
completely, but consistently shifted their remaining errors to SITTING vs. STANDING instead.
Sequence length mattered far more to RNN (F1 rose from 72.45% at T=32 to 86.29% at T=128)
than to GRU, which was already near its ceiling at T=32. The additional-exercise sweep also
showed that more capacity/depth is not automatically better: a 2-layer LSTM (81.94% accuracy)
was clearly worse than the 1-layer version (95.83%), the single most surprising result in the
whole experiment.

## Dataset

**UCI Human Activity Recognition Using Smartphones** — loaded from the raw inertial signal
files (not the pre-computed 561-feature vectors), so both spatial and temporal information
in the sensor stream is preserved.

- 7,352 official training windows and 2,947 official test windows, each 128 time steps long
  with 9 channels (three-axis body acceleration, three-axis gyroscope, three-axis total
  acceleration): $X \in \mathbb{R}^{N \times 128 \times 9}$
- A balanced 2,400-window laboratory subset (400 windows per activity) is drawn from the
  training partition, then split 70/15/15 into this experiment's own train/validation/test
  sets — 1,680 / 360 / 360 windows, 280/60/60 per class
- Normalization statistics (mean/std) are computed from the training split only and applied
  to validation/test
- The test set is never touched until Section 14's final evaluation

**UCF101** (video section) — a small subset of 3 classes (Basketball, Biking, TennisSwing),
8 videos each, downloaded and cached once. `WalkingWithDog` and `Running` were not used since
"Walking"/"Running" are not exact UCF101 folder names.

**Synthetic reversal task** (seq2seq section) — 6,000 generated 4-digit sequences, no external
download required.

## Getting Started

### 1. Clone the repository

```bash
git clone https://github.com/<your-username>/<your-repo-name>.git
cd <your-repo-name>
```

### 2. Set up a virtual environment (recommended)

```bash
python3 -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
```

### 3. Install dependencies

```bash
pip install -r requirements.txt
```

### 4. Run the notebook

```bash
jupyter notebook Deep_Learning_Lab_6_RNN_LSTM_GRU.ipynb
```

or open it directly in [Google Colab](https://colab.research.google.com/) / Kaggle (GPU
runtime recommended for the CNN feature extraction and 30-epoch RNN/LSTM/GRU/CNN-LSTM
trainings) and run all cells top to bottom. The notebook downloads the UCI HAR dataset and
the UCF101 subset itself, and caches both to Google Drive so a later re-run of the code does
not re-download them - nothing needs to be fetched by hand.

## Building the Report

The LaTeX report lives in `report/main.tex` and pulls in the figures from `report/figures/`.
The figures are already PDF (not EPS), so no `-shell-escape` flag is required.

1. Upload `report/main.tex` and everything in `report/figures/` into an
   [Overleaf](https://www.overleaf.com/) project (same folder level - keep the `figures/`
   subfolder as is).
2. Compile with pdfLaTeX.

Or locally:

```bash
cd report
pdflatex main.tex
pdflatex main.tex
```
